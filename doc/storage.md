# Storage compatibility

Kobalt separates saved reading data from disposable rendering caches. Storage formats are versioned independently of application releases. Hosts choose the storage directory; `storage::Paths` owns the shared filenames. JSON uses UTF-8. Writes use `QSaveFile` to replace a complete file atomically.

## Saved reading data

`reader-settings.json` holds global preferences with `schema: 1`. Unversioned settings are upgraded atomically. Recognized retired settings are converted or removed, invalid known values fall back to their defaults, and unknown keys are preserved. Unsupported future versions block writes. `config.json` remains the small Kobo enable/disable configuration.

`tappable_links` is an optional global setting with values `off`, `footnotes` and `all`. Missing or invalid values use Off. It does not change the settings schema or parsed-book cache format.

`dictionary_font_face` and `dictionary_font_size` are optional global preferences. An empty or missing face follows the current book’s resolved body font, including its normal reading-font fallback. A missing size uses 100 percent. Supported sizes are 80, 100, 120 and 140 percent. Invalid values use these defaults. These settings affect dictionary definition text, not book layout or saved annotations. They keep preference schema 1.

`vertical_justification` is an optional global setting with values `off`, `expand` and `center`. Missing or invalid values use `off`. The Boolean used by early development builds maps to `expand` or `off`. `vertical_spacing_scope` selects `all` or `protection`; missing or invalid values use `all`. These fields keep settings schema 1 and canonical reading positions. Parsed-book cache format 6 stores source line boxes and whether a page gap was caused by widow/orphan protection. Older rendering caches rebuild without changing saved reading data.

Book state now lives in `kobalt.sqlite`. Legacy book state uses a host-selected prefix followed by the SHA-256 of the UTF-8 book identity and `.json`. Its `schema` is `1`. The `book` and `fingerprint` fields identify the publication. It stores the canonical reading position, book-specific text preferences and native progress reconciliation fields. Globally owned layout preferences remain in global settings. Marking a book unread resets its position and book-specific preferences, but keeps annotations.

Legacy JSON bookmarks and annotations share `annotations/<book-key>/`. `book.json` has `version: 1`, `identity`, `title` and `fingerprint`. Book keys come from `BookmarkStore::bookKey`: native book identities remain stable across downloads; sideloaded books use their content fingerprint. A changed file can adopt annotations from the previous record of the same path.

`bookmarks.json` has `version: 1` and a `bookmarks` array. Each bookmark stores `position`, `chapter`, `excerpt` and `created`. Positions are canonical CREngine XPointers, not page numbers. Dates are UTC ISO 8601 strings.

`highlights.json` has `version: 1` and a `highlights` array. Each entry stores `id`, `start`, `end`, `text`, `chapter` and `created`. Optional `color` defaults to `gray`; optional `style` defaults to `shaded`. Supported styles are `shaded`, `underline` and `dotted`. Unknown color and style tokens survive edits and use a display fallback. Optional `sentence_start` and `sentence_end` objects preserve endpoint provenance through `enabled` and `chosen_start` or `chosen_end`.

An optional `note` string holds plain text for a future note editor. Missing notes mean empty text. Notes preserve Unicode and line breaks and are limited to 65,536 UTF-16 code units. Passage edits and appearance changes preserve the note. Beta 4 does not expose a note editor. Adding this optional field does not change format version 1.

Each book supports up to 2,000 bookmarks and 2,000 annotations. Bookmark files are limited to 1 MiB and highlight files to 8 MiB. An annotation excerpt is limited to 262,144 UTF-16 code units. Malformed or unsupported annotation files block subsequent saves rather than replacing the original data with an empty list.

Add compatible optional fields within version 1. A change to required fields, their meaning or location needs an explicit format version and migration. Do not tie data versions to release names. This is the current format contract, not a promise that older builds preserve arbitrary unknown fields. Book-state imports reject unsupported schemas without replacing the source. Database record formats are versioned separately and unsupported formats block updates.

## SQLite profile database

Beta 4 uses SQLite by default for bookmarks, annotations, book state, the standalone Library catalogue, recent-book metadata and aggregate reading speed. Global settings remain JSON. Set `KOBALT_ANNOTATIONS_SQLITE=0` to select the legacy JSON backend for diagnostics, or configure a diagnostic build with `-DKOBALT_SQLITE_ANNOTATIONS_DEFAULT=OFF`. An explicit environment value of `1` selects SQLite even in that build. Backend selection is captured when each store is constructed. Do not switch backends while a book is open.

The database is `kobalt.sqlite`, directly in the profile directory alongside `reader-settings.json`, outside the rendering cache. Legacy JSON sources originate under `annotations/`; profile preparation archives completed imports under `migration-backup/annotations/`. It has application ID `KAN1`, UTF-8 database encoding and schema version 2 in `PRAGMA user_version`. This version is independent of the JSON format version and application release. Opening checks the encoding before any persistent configuration change and rejects other encodings without converting them. Stored strings use explicit UTF-8 byte binding and are selected as bytes for decoding with an explicit length. This preserves embedded NUL characters and literal leading U+FEFF characters across Qt providers. Unknown, foreign or damaged databases are rejected without recreating their schema. Future incompatible schemas need explicit transactional migrations before their version changes.

The first opening imports a book's bookmarks and highlights in one transaction. Beta 3 has version-1 bookmarks and no highlight file. Later version-1 highlights can include colors, styles, endpoint provenance and notes. Imports preserve those fields, IDs, timestamps and record order. They keep the original JSON files unchanged. An interrupted import can retry without duplicating records. Invalid or unsupported source data blocks the import instead of silently discarding it. Fingerprint adoption checks committed database records and unmigrated JSON sources; retained JSON from an already imported book does not replace newer database edits.

After import, SQLite is the authoritative store for that book. The retained JSON files are import snapshots, not current exports. An older application can edit those snapshots without updating SQLite. Reinstalling an older build is therefore not a supported way to transfer new database edits back to JSON; that needs an explicit compatible export and conflict handling.

The annotation format permits gaps in stored order values. The upgrade path imports Beta 3 and current JSON records into this database. Negative, non-integer and duplicate order values are rejected. Deleting an entry preserves every surviving order value; appending assigns the next value. Explicit reordering, insertion before an existing entry or exhausting the signed 64-bit range can assign a new sequence.

Each load reads its metadata, payload bounds and records from one transaction snapshot. Each save changes only added, modified, removed or reordered rows. A per-list revision rejects stale writers. A failed transaction preserves the prior saved list, and the session restores its in-memory list. The database keeps the existing per-book count and encoded-size limits. It requests a 2 MiB page cache and disables memory mapping. The cache setting is not a total process memory limit.

The reader can load compact highlight records with IDs, endpoints, provenance, appearance and timestamps. Compact records do not retain excerpts, chapter labels or notes. A visible-list request reads only its requested excerpts and chapter labels. Opening an individual record for editing reads its complete details. Both requests use the revision of the compact list and reject a concurrent change. The ordinary full-load API and JSON backend keep their existing behavior.

Compact loading checks SQL field-byte bounds, metadata, IDs, count, ordinal order and stored byte totals. It also rejects a payload whose raw byte lengths exceed its stored encoded size. It does not recompute the exact JSON-equivalent size or UTF-16 validity of unloaded payloads. Excerpt requests validate the fetched text and chapter limits; complete detail requests validate every field and recompute the exact encoded row size. This deferred validation means a damaged unloaded payload can remain undiscovered until requested. A compact appearance edit reads and validates that row's full details within the write transaction before preserving its excerpt and note. Endpoint edits require complete details. Deletion does not read the deleted payload. Successful compact saves discard loaded payloads again, and read-only detail requests do not populate the store's retained records.

## Profile connection

One writer thread owns `kobalt.sqlite`. Every read and write runs on that thread, one at a time, through one connection. No other code opens the file while that connection is open. Operations from other threads wait for their turn; calls that a caller waits for run before waiting background writes, but a background write that has waited two seconds runs next. Only Kobalt writes this file.

The connection takes an exclusive lock before its first read and keeps it until it closes. It uses write-ahead logging: a commit appends to `kobalt.sqlite-wal`, and a checkpoint folds the log into the main file. With the exclusive lock, SQLite keeps the log index in memory and creates no `-shm` file. Commits use `synchronous=FULL`, which syncs the log. Routine position and reading-speed saves use `synchronous=NORMAL` and do not sync; the next synced commit, a checkpoint or the close puts them on storage. A crash of the process loses no commit. A power loss can lose routine saves that were not yet synced, but not a synced commit, and it does not corrupt the database. If SQLite refuses write-ahead logging, the connection keeps a DELETE rollback journal with `synchronous=EXTRA`.

Opening reads and checks ownership, version, encoding, page size and all eight tables before its first change to the file, the switch to write-ahead logging. A rejected file keeps its content; only a log left by a crash is folded into it. Opening also refuses a read-only file, so no connection stays open that cannot write.

The connection checkpoints at sleep. Before standby it checkpoints when routine saves are not yet synced and the last sync is at least a minute old. After a failed checkpoint, standby waits five minutes before it asks for another, and the failure is kept in the durable diagnostics log. It closes when a book closes, after the reader is disposed for a transition, at USB export and at power-off. Closing waits for waiting writes, checkpoints, returns the file to a DELETE rollback journal and closes it. A copy, a computer over USB and older builds then see one ordinary file. After the close at USB export and at power-off, every operation fails until the partition is mounted again or the USB connection ends before the export. The firmware unmounts the partition lazily before export and freezes Nickel at power-off, so no file may stay open then. The first operation after a close opens the file again.

A process that ends without closing leaves `kobalt.sqlite-wal`. The log belongs to the database: copy or remove both files together. The next opening replays it. Earlier builds also replay it when they open the file, and return it to a DELETE rollback journal.

Book state, bookmark, highlight and reading-speed writes are background writes. Each owner keeps at most one waiting write; a newer write of the same record replaces it. Synchronous saves at opening, sleep, USB, close and power-off wait for their result. Bookmark and highlight edits show at once. When the newest save fails, the session restores the last saved list and reports the error. USB export and power-off wait for waiting annotation writes. Saved data must stay outside `.cache/` even when the database schema changes.

The connection sets `max_page_count` from the database page size to keep the main file below FAT32's 4 GiB per-file limit. This does not bound the log or journal size or guarantee free disk space. SQLite's automatic checkpoint folds the log into the main file after about 1000 pages. A database already larger than that limit is rejected without changing its contents. Initial schema creation uses a temporary sibling file and an initialization lock. The complete database is published by rename, followed by a directory sync; an unpublished staging file does not block a later retry.

## Annotation exports

Annotation exports are compressed ZIP snapshots for reading outside Kobalt. Each archive contains one selected UTF-8 file: `annotations.md` or `annotations.html`. Both documents group consecutive chapter labels in source order, label entries as annotation numbers and omit page numbers. HTML uses compact `#1`, `#2` links and renders the saved marker, solid underline or dotted underline in the reader’s color palette. Unknown styles and colors use the same display fallbacks as the reader. The app embeds bundled Libron Regular as a base64 font for passages, with a non-visible HTML comment referencing the SIL Open Font License (OFL) 1.1. Missing font assets leave a system-serif fallback. Each entry includes its creation timestamp. Markdown shows UTC explicitly. HTML starts with UTC fallback text and formats timestamps in the browser’s locale and timezone when JavaScript runs. HTML has embedded styles, search and Book order, Newest first and Oldest first sorting. Date sorts use the original instants, with source order as the tie-breaker, and keep annotation numbers unchanged. The HTML needs no external files, network requests or browser storage, including when opened from a `file:` URL. The Nickel integration writes them under `/mnt/onboard/Kobalt/Annotations/`. Mac and Android use Qt's native save picker to select a filename and location. Export fetches complete saved records in one revision-checked request, including notes omitted by compact loading. Export requires a confirmation naming the book and ZIP contents. It hydrates and sorts the snapshot using resolved source positions, then builds the archive before opening the picker. Kobo requires a distinct Replace ZIP approval for an existing destination and checks again before writing if a file appeared during the initial confirmation. The native picker keeps overwrite confirmation enabled on other platforms. Exports wait for the annotation list’s location lookup; unresolved passages sort after resolved passages in their saved order. Suggested filenames combine a sanitized title and the first 16 hexadecimal characters of the SHA-256 book identity, followed by `-markdown.zip` or `-html.zip`. The two formats never share a default destination. Local destinations use `QSaveFile`, which replaces an existing export only after the complete snapshot is written. Android `content:` destinations use the picker-granted access and a direct `QFile` write; atomic replacement depends on the document provider. Cancelling the picker writes nothing. Exports are not backups for importing annotations, do not change saved-data versions and do not modify Nickel settings. The checked Show annotation styling option below search hides or restores marker fills and underlines. It keeps passages, notes and the embedded font visible, and applies to printing.

## Disposable caches

`.cache/` belongs exclusively to CREngine. Never put settings or annotations there: the engine removes files it does not recognize. It stores parsed books in an engine-specific binary format, with a 128 MiB budget. It is not an interchange or backup format.

The cache checksum includes an explicit Kobalt parser format version and the document DOM version. Build policies on all platforms include the pinned rendering dependency manifest, dependency recipe, patches and bundled hyphenation pattern names and contents. Adding, changing or removing a dictionary rebuilds disposable caches so old pagination does not survive a pattern change. App version strings and UI source changes do not invalidate parsed books. Bump the format version in `documentCacheChecksum` when a parser or preprocessing change makes existing cached documents unsafe to reuse. Density, user CSS and bold-reading variants retain their existing policy checks. Changing typography can still require pagination without reparsing the publication. A dependency or format change can intentionally cause one new parse.

`cache/reopen-layout.json` is a separate bounded, version-1 cache of publication inspection results. Its policy follows the build's layout policy. It can be discarded without losing reading data. Bump its format version when inspection verdict rules change incompatibly, independently of the parsed-document format.

`cache/sleep-screen.png` is a disposable Kobo power-screen backdrop saved when a Kobalt book closes or completes its final USB save. PNG metadata version 1 stores the last-read record token, selected mode, orientation, progress, remaining-time text, theme and whether the page needs dimming. It also stores the percentage read. Images saved without it still load; the styles that draw it then leave it out. The status tile is composed when the device sleeps or turns off, in the style selected at that time. The file is replaced atomically and is limited to 20 MiB and 4,194,304 pixels. A new book opening removes it. Missing, damaged, unsupported or stale images fall back to Kobo's built-in sleep screen. It is separate from CREngine's `.cache/` and contains no authoritative reading data.

## Profile migration and cleanup

SQLite schema version 2 includes annotations, JSON profile records and the Library catalogue. Beta 3 and supported version-1 JSON data import directly into this schema. Only SQLite schema version 2 is supported. Other versions and partial schemas are rejected without repairing or replacing the database. Initial database publication includes every table.

`book_state(identity, format, revision, payload)` stores one JSON object per publication identity. Its encoded payload is limited to 16 KiB. `profile_state(name, format, revision, payload)` stores application records such as reading speed and recent-book metadata. Recent-book metadata permits 256 KiB; other callers retain the 16 KiB limit. Payloads use compact UTF-8 JSON, checked in the application without SQLite JSON extensions. The record format remains 1, independently of the database schema. Unsupported record formats and malformed or oversized payloads block updates. Optional fields, nested values, Unicode and embedded NUL characters survive JSON import and edits.

Unchanged checkpoints do not write their row. A changed checkpoint replaces only that book’s JSON object and increments its revision in the same transaction. The revision counts changes; it is not a stale-writer token in the current checkpoint API. Reading positions, text overrides, dictionary choices and native progress reconciliation retain their existing meaning. Mark as unread replaces the book record with an identity-only checkpoint. Bookmarks and annotations remain in their indexed tables and are not included in this JSON object.

`library_books` stores one row per discovered book, including its source key, folder, metadata, cover filename, timestamps, progress and explicit read status. `library_folders` stores folder keys, labels and display order. Library view, sort and filter preferences live under `library` in `reader-settings.json`. Saving an unchanged book does not rewrite its catalogue row. Kobo continues to use its native library rather than these tables.

`imports(source, digest, record)` records successful JSON imports inside their data transaction. A retry uses the committed database record, never stale JSON. After commit, the original source is moved into `migration-backup/`. Its digest is checked before the move. A failed move can retry without importing twice. Book state and annotations from Beta 3 and current version-1 JSON sources are supported. Library migration rejects duplicate identities, missing folders and unsupported versions rather than dropping records. A failed Library import blocks catalogue saves and shows an error instead of creating a replacement empty catalogue.

Profile preparation imports recognized hashed book-state files and annotation folders, including books not reopened after the upgrade. On Kobo it runs at the first reading request, after the loading view paints, rather than during native startup and library initialization. Annotation imports retain source timestamps so a changed sideloaded book adopts the newest saved edition rather than whichever folder was migrated last. Imported annotation folders and their derived path index move under `migration-backup/annotations/`. Unknown files, symbolic links, malformed sources and unsupported formats are left untouched. Keep the migration backup until the upgrade has been validated. It is a historical snapshot, not a current downgrade export. Do not install an older build expecting it to read subsequent SQLite edits.

The old root inspection cache moves to `cache/reopen-layout.json`. Parsed engine books remain exclusively under `.cache/`. Existing inspection reports and bounded logs move under `migration-backup/diagnostics/`, so they cannot replace a new session’s diagnostic output. Kobo generates new inspection reports and logs only when `KOBALT_DIAGNOSTICS=1` or a `diagnostics-enabled` file exists in the profile. These files are not reading data. The standalone `active-session.json` and `startup-session` safety markers keep their recovery behavior.
