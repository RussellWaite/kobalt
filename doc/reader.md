# Reader behavior

This document describes what Kobalt does on a device today: which builds exist, how to install and remove them, what the reader supports and what is still unverified. Build commands are in the [build guide](building.md). Saved data and cache compatibility are described in [Storage compatibility](storage.md).

## Builds and firmware

Kobalt has two Kobo builds. Each build matches the Qt version of its firmware.

| Build | Firmware | Qt | System package |
|---|---|---|---|
| `qt5` | 4.38.21908 and later 4.x | 5.2 | `KoboRoot.tgz` |
| `qt6` | 5.18 and later 5.x, and 6.x | 6.5 | `Kobo.tgz` |

The first public beta, `v1.0-beta.1`, includes only the Qt5 package. Qt6 remains a development build.

No build checks the device model or display driver. At startup, each build checks its required Nickel symbols and the registered size of Nickel's `Volume` type. The `qt5` build finds the unexported orientation singleton by its machine code and requires it to match exactly once. If a check fails, Nickel keeps its own reader. A release that keeps every symbol but changes another object size or a virtual-table slot is not detected.

## macOS testing app

The Mac app uses the same reader controls and renderer as the mobile app. The title bar is blank and keeps the standard window controls. The app opens in the [library](#library). Open an unprotected EPUB from there, File → Open EPUB, Command-O, Finder's Open With, or by dropping one EPUB onto the window. Each opened book joins the library. File → Add Library Folder scans a folder. Removing a book from the library never deletes the file. Opening another book saves and closes the current book. The reader's Exit Kobalt button returns to the library.

The app starts with the six-inch e-reader preview at 300 DPI. The toolbar shows the Kobalt icon on the left, the screen and rendering-resolution pickers in the center and the application version on the right. The picker selects Fill window, 6-inch e-reader or 7-inch e-reader with buttons. Fill window changes the reading viewport when you resize the window and keeps controls the same size on standard and Retina displays. Moving the window between monitors or changing the monitor DPI redraws the reader. Text reflows after the resize settles. The 6-inch preset uses a 1072 × 1448 screen and the 7-inch preset uses a 1264 × 1680 screen, both at 300 PPI. These match Clara Colour and Libra Colour screen specifications. Rotate in the toolbar or View > Rotate Device (Command-R) switches either e-reader between portrait and landscape. The frame and page buttons rotate with the device, and the book reflows without reopening or losing its reading position. Rotation stays selected when switching between device presets and is unavailable in Fill window. Each device preview has a black rounded body and a black screen border, without logos. The 7-inch preview has a wider side grip with working Previous page and Next page buttons without icons. All modes use the same 300 PPI layout for reading settings and controls. The second picker offers 212 DPI, 300 DPI and Native, with 300 DPI selected initially. The fixed resolutions produce a device image and use smooth filtering when fitting it to the window. Native draws controls at the Mac display resolution, including Retina pixels. Switching rendering resolution preserves the frame, book layout, page count and reading position. Book pages remain images at the layout resolution and are smoothly scaled when Native needs more pixels. Switching screens reflows the current book without reopening it. Device previews always show a simulated status bar with a fixed 09:00 clock and full battery. Fill window follows the saved status bar preference. Dictionaries is available in Fill window and hidden in device previews. In device previews, tap within the middle third of both the screen width and height to open or close the reading menu. While a Text or Layout panel is open, a tap anywhere on the visible page closes it. These presets simulate layout and text density, not the colour filter or e-ink refresh. Left and Right, or Page Up and Page Down, turn pages while reading. Reader controls remain available through the page's touch-style controls. Mouse and trackpad clicks use the same controls: click the center of the page to show the reading menu, or the left and right sides to turn pages. Closing the window saves the reading state and waits for the engine to finish.

View > Device and View > Rendering Resolution offer the same choices as the toolbar. Their checkmarks follow the toolbar selections. View > Show Toolbar hides or restores the preview toolbar; Option-Command-T does the same. The toolbar context menu uses the same Show Toolbar action, so a hidden toolbar can always be restored from View. Hiding or showing it fits the reading area again. Fill window reflows to the available space; device frames keep their fixed layout and page count.

Settings, bookmarks, reading positions and cached layouts stay under `~/Library/Application Support/Kobalt/Kobalt/config/`. A build from a Git worktree uses its own profile; see [Building](building.md#mac). Logs go to the adjacent `diagnostics/` folder. Add personal reading fonts to the adjacent `fonts/` folder and reopen the book. Bundled fonts come from the app, so the reader does not depend on macOS font fallback.

The gear in the toolbar opens Settings. Its tabs show an icon above a label, as the bottom tabs do. Defaults appears immediately below Controls, and new-book inheritance and Restore appearance defaults belong there. Fonts follows Defaults and selects generic-family fallbacks. Books uses a stack-of-books icon and contains book-content options. The tab rail is as wide as its widest visible label, so it narrows where Dictionaries is not shown. Its rows have two extra pixels above and below at 300 PPI and fit the available height. Settings > UI appears below Books in Fill window mode on Mac, with a desktop icon. Device previews hide this tab. Switching to a device preview while UI is open returns to Display without changing saved UI preferences. Hide status bar is enabled by default. It hides the Battery slots and the menu status row; the header and footer keep the time and their other slots. Unsupported hardware options remain visible and explain why they are disabled. Each settings option and list action draws its own bottom divider, including the last row in a tab and the choices in the screen-refresh popup. The refresh choices use equal-height rows with edge-to-edge separators and a top rule; adjacent rows share one separator. Remaining controls keep their normal height, with spare space below them. These preferences persist on the Mac and do not change the screenshot fixture.

This build is for renderer testing. It has no Nickel library integration, brightness controls or e-ink refresh. Downloaded dictionaries work on desktop and Android. Vertical text uses the same layout engine as the device builds. See [Building on macOS](building.md#mac).

## Installation

For the first public beta, download `Kobalt-qt5.zip` from the release. To build a firmware 4 package locally, run `bash platforms/kobo/build.sh qt5` and use `build/kobo-qt5/Kobalt-qt5.zip`.

1. Extract the full ZIP on your computer and show hidden files.
2. Copy the complete `.adds` folder from the ZIP to the root of the Kobo drive. Merge folders and replace matching package files. Keep other apps, settings and reading data.
3. Copy the complete `.kobo` folder from the ZIP to the same drive root. Merge folders. It contains `KoboRoot.tgz` for firmware 4 or `Kobo.tgz` for firmware 5 and 6. Do not unpack this archive yourself.
4. Eject the device safely, disconnect USB and let Nickel install the update.

Copy every file supplied in the ZIP, keeping its folder path. Copy `.adds` first so the required resources are present before the update starts. Kobalt creates its support files and `.adds/kobalt/.initialized` installation receipt on first startup. Updates move the older `.adds/.kobalt.initialized` receipt into that folder.

The system package holds only `libkobalt.so`. Fonts, hyphenation dictionaries and the asset manifest go to `.adds/kobalt/assets/`. `manifest.json` names the release version and the size and SHA-256 of each file. If an asset is missing, damaged or belongs to another version, Kobalt keeps its native settings and book-menu reader choice available. Trying to open a book with Kobalt shows a Nickel system dialog titled “Kobalt can't start”. It explains the resource problem, asks you to reinstall Kobalt and shows the installed version. OK returns to the library without opening the book. The event log records `assets-unavailable`. If asset validation fails and the assets folder contains `FSCK0000.000`-style recovery files, the dialog explains that the filesystem may have recovered files under different names. The event log also records `asset-filesystem-recovery`. Kobalt first checks recovery files in the missing asset’s directory. If a file’s size and SHA-256 match the manifest, it renames that file to restore the missing asset and continues validation. It never replaces an existing asset or changes an unmatched recovery file. This restores filenames only; it does not repair the filesystem. An update replaces the managed asset files and keeps settings and saved positions.

Updates from early test builds that used a different plugin name require manual removal of that older plugin and its failsafe copy before installing Kobalt. The current build does not migrate or remove older plugin names.

## Removal and recovery

A normal build stays installed across restarts. To remove it, delete `.adds/kobalt/uninstall` or the whole `.adds/kobalt` folder, then restart Nickel. Removal keeps other files in `.adds/kobalt` unless you deleted the folder. On supported Kobo firmware, an initialized Kobalt watches a confirmed USB session for removal of the `uninstall` marker. After storage remounts and Nickel finishes processing, it shows “Removing Kobalt” and “Restarting your device...” and requests a normal system restart after three seconds. The message lasts ten seconds so it stays visible beyond the restart delay and into shutdown. Restarting does not depend on whether Nickel can display the message. If Kobalt is inactive, restart the device yourself.

A previously installed temporary build writes `.adds/kobalt/uninstall-now` before it activates. The next Nickel start removes the library, also after a crash.

Kobalt uses two session markers:

- `startup-session` exists during a synchronous initialization attempt. A crash during that attempt leaves the marker. Waiting for Nickel or a usable screen, or deferring a completed attempt, does not leave it.
- `active-session.json` exists while a book is open or opening. A clean exit, a cancelled opening, a fallback to Nickel, power-off and reboot remove it.

If `startup-session` is present at startup, Kobalt stays inactive and Nickel keeps its reader to prevent a startup crash loop. Read the event log first. Then stop Nickel, delete that marker and start Nickel again to retry Kobalt. A leftover `active-session.json` does not block startup. Kobalt can open a book again after an interrupted reading session or a forced reboot.

NickelHook also parks the library outside `imageformats` for the first three seconds after Nickel starts. A crash in that interval leaves the library parked and inactive. If the restore thread cannot start, the library stays parked for the next startup. Failed initialization restores installed hooks in their original libraries. Install a fresh package to recover. Do not move a parked library back by hand.

To install a new build over a temporary build, copy the new package, then delete `.adds/kobalt/uninstall-now` before you eject. If you leave it, the next start removes the new library.

Kobalt waits for Nickel to finish initialization before creating its reader controller. If Kobalt misses the completion callback, it can recover by checking the existing Power Manager and Nickel's application connection. The check does not create the manager. An unrecognized native layout cannot enable recovery. If native readiness is still unconfirmed after 30 seconds, Kobalt records `startup-failed` and keeps the built-in reader active for that boot.

## Files on user storage

Support files are in `.adds/kobalt/`. Annotation exports are in `Kobalt/Annotations/` at the root of the Kobo drive.

| File | Contents |
|---|---|
| `assets/` | Bundled fonts, hyphenation dictionaries and `manifest.json` |
| `config.json` | `enabled`, the Open books in Kobalt choice |
| `reader-settings.json` | Settings that apply to every book: display options, Bold Reading, default reading font, interface preferences, new-book inheritance options and the last text/layout and header/footer settings |
| `userstyle.css` | Optional user CSS for every book; create and edit this file yourself |
| `<hash>.json` | One file per book: saved position, typography, header and footer preset, orientation, dictionary choice and the Nickel progress baseline |
| `annotations/<key>/` | One folder per book with `bookmarks.json`, `highlights.json` and `book.json`, see Bookmarks and annotations |
| `annotations/.index/paths.json` | Disposable bookmark lookup index, at most 4 MiB; rebuilt from book folders when missing or invalid |
| `reopen-layout.json` | Up to 20 layout-check results, keyed by archive digest, at most 8 KiB |
| `.cache/` | Parsed books and their pages, so a book that was opened before opens without parsing. At most 128 MiB; the oldest books are removed first. Kobalt deletes any other file in this folder |
| `events.jsonl`, `events.jsonl.previous` | Event log, two files of at most 128 KiB each |
| `state.json`, `session.json` | Reader state from the last close, sleep or shutdown, and session status. Create `live-state` to write `state.json` on every save instead |
| `startup-session`, `active-session.json` | Recovery markers, see above |
| `uninstall`, `uninstall-now` | Removal control, see above |
| `doc` | Short user instructions |

The event log records startup checks, opening stages, timings, memory and save results. The startup event includes the firmware version and hardware UUID when available. The hardware UUID identifies the model, not an individual device. Startup events also record hook availability, entry and return of Nickel initialization, periodic wait state and book-opening retries. Archive inspection failures include the specific `error_code` in the `native-resource-failed` event with stage `publication-inspection`. It does not record book text, titles, file paths, serials or account data. A position fallback records the name of the chapter file inside the book. `state.json` and `session.json` can contain book identifiers, so keep them private. The log shows the last recorded operation, not a crash stack trace.

On Kobo models with a physical Home button, pressing it closes Kobalt and returns to Nickel's Home screen. Kobalt saves reading progress before leaving. Any progress or finished-book choice shown during a normal exit still applies. Sleep cancels a pending return to Home and restores any exit choice after wake. In sideload mode, Nickel returns to My Books.

## Opening books

The default build opens unencrypted local EPUBs selected through Nickel, regardless of their folder. This includes onboard and SD storage, hidden folders, Kobo's built-in Dropbox and Google Drive downloads, and folders used by third-party sync services. Local files can have any filename or use a symlink; Nickel's EPUB MIME type and Kobalt's archive inspection determine whether they are supported. DRM-free Kobo purchases also open, including extensionless books stored by Nickel. Embedded TrueType and OpenType fonts using IDPF or Adobe font obfuscation are supported. Adobe font obfuscation requires a UUID in the book's metadata. These font embedding methods are not DRM. Other resource encryption and unsupported font obfuscation still use Nickel. Book previews, PDFs and protected books use Nickel's reader.

When Kobalt is the default reader, the library’s long-press menu offers Read with Nickel for EPUBs, including protected books and books remembered as needing the native reader. This choice does not require Kobalt to read the publication. When Nickel is the default reader, Read with Kobalt still requires Kobalt eligibility. Previews, unsupported formats and disabled native Read now actions keep their native menu. The choice applies only to that opening.

On firmware 4, sideloaded filenames and saved chapter prefixes preserve literal `#`, `?` and percent sequences such as `%20`.

Loading a local book does not require Wi-Fi or an internet connection. Kobo, Android and desktop read unencrypted EPUB resources directly from the ZIP archive on the engine worker, without a loopback HTTP server. The existing source cache, resource and image limits, cancellation and access-revocation checks still apply. Each resource stream closes before its read finishes, and closing or exporting a book drains the worker before releasing the publication.

Resource reads reuse one archive directory index per publication instead of scanning the ZIP directory for each chapter or image. The index retains at most 4 MiB of directory bytes and 4,096 entry offsets. It holds no resource bytes or open files. Changed file metadata invalidates it. Each resource still checks its local header and CRC.

Kobalt removes the recognized original `kobostylehacks` CSS block from chapter input before rendering. This restores publisher heading and paragraph spacing, relative font sizes and link colours. The book file stays unchanged. The wrapper-only rule used by kepubify and blocks with unknown or custom additions remain intact.

Nickel stays responsible for authorization. Kobalt receives an opening only after Nickel accepts it, then reads the EPUB's ZIP entries directly. It checks the publication structure and lets CREngine load its reading sections before displaying the book. Protected content, source access failures and books the engine cannot load still offer fallback to Nickel. A store purchase keeps its existing book identity and uses the same progress, completion and sync integration as before. Direct loading does not turn it into a sideloaded book.

Kobalt lets CREngine try to open books when the layout check finds unsupported declarations or cannot finish inspecting their formatting. A confirmed unsupported layout feature shows a warning icon beside Bookmarks in the reading menu. Tap it to see a notice that some text or layout may not appear as intended. The warning stays available after page turns and reopening. Inspection limits, parser errors and missing stylesheets stay in diagnostics without a formatting warning. Archive validation, source access failures, protected content and unreadable publications still stop opening. On Kobo, an opening failure offers the built-in reader.

The layout check inspects linked stylesheets declared as CSS or without a type. It ignores Adobe page templates and other explicitly declared types that CREngine does not use. Missing Adobe page templates do not cause a formatting warning. Missing CSS makes the inspection incomplete and records the missing reference in diagnostics.

The `layout-compatibility` log records the first inspection issue, the publication resource and a source excerpt of at most 240 characters. XML failures include the parser message, line and column. The excerpt can contain book text. A successful opening with a confirmed unsupported feature also records these details in `opening-formatting-warning`. A retained-book reopening keeps the warning details and sets `retained_book_hit`.

Nickel's Reading Settings has a Kobalt section with Open books in Kobalt. It is on after installation. Turning it off sends later openings to Nickel's reader and keeps Kobalt installed. Long-press a book to open it once with the other reader, without changing the setting.

Kobalt supports horizontal Chinese, Japanese and Korean text and Japanese vertical text declared with `writing-mode: vertical-rl`. The `-epub-` and `-webkit-` forms are also supported. A book can alternate vertical and horizontal chapters. Blocks that change writing direction within a chapter start on separate pages. Mixed directions within a paragraph are accepted, but may render sideways, overlap or extend beyond the page. `vertical-lr`, sideways modes and legacy vertical declarations remain unsupported by the renderer; Kobalt tries to open these books with a formatting warning. Language alone never selects vertical writing. Use a font with vertical glyphs, such as the bundled Noto Serif CJK.

If Kobalt cannot load an EPUB, it keeps the full-screen Kobalt view and shows a confirmation card titled “Couldn't open this book”. Choose “Try built-in reader” to let Kobo try the original opening request, or “Go back” to cancel. Kobalt checks authorization again before continuing. A book with explicit protection metadata shows a lock and “Opening with Kobo's reader”, then continues automatically after three seconds. During handoff, a temporary copy of the splash covers the library while the native opener runs. The modal Kobalt window closes first, so native messages remain visible. The copy is removed when the native opener returns. Protected routes and accepted “Try built-in reader” choices after a completed content rejection are remembered in memory until Nickel restarts. Authorization, resource-transfer and saved-position failures are not remembered. Reopening an unchanged remembered book shows the handoff screen for three seconds without retrying Kobalt. Changing the book file invalidates its remembered route. “Go back” does not remember a failed opening. An unreadable file alone is not treated as proof of DRM. Previews, PDFs and other unsupported formats open directly in the built-in reader without a Kobalt screen.

While a book is open, Kobalt checks authorization again after sync, a profile update, a volume change and wake. Removal of the book, sign-out, a change of account, subscription closure and loan denial close the book. Closing for authorization saves only the local position.

Closing a book keeps its parsed document in memory. Reopening the same unchanged book is faster, but still goes through Nickel's opening and authorization checks. Opening another book, USB, account changes and restart discard the kept document.

On Kobo, closing a book also saves its parsed document and its pages in `.adds/kobalt/.cache/`. A later opening of the same unchanged book restores them instead of parsing and laying out the book again, also after a restart. Different typography or screen size reuses the parsed document and lays out only the pages. Kobalt still reads one chapter file through Nickel before it opens a cached book, so authorization is checked as for any other opening. A changed book file, a different Kobalt release version, or a different engine version opens without the old cache entry. After a successful cache save, Kobalt removes older cache entries for the same book. Entries for other books remain available. The cache holds at most 128 MiB and removes the oldest books first. With less than 256 MiB free on user storage, books open and close without it. A failed write to the cache leaves that entry unused and does not interrupt reading.

## Reading position and progress

Kobalt saves the position in its own per-book file and writes it back to Nickel when the book opens, every 30 seconds while reading, before sleep and when it closes. Background saves skip an unchanged position and wait until the reader is idle. A busy database or newer synced progress keeps the local position without overwriting Nickel. The first opening imports Nickel's saved position. On later openings, a newer Nickel position wins over the local one. Like Nickel's reader, the write at opening marks the book as the one being read, so Home and the sleep screen show it. Sleep saves the local position and attempts native progress writeback before Nickel prepares its sleep screen. Like Nickel's reader, Kobalt opens every saved position: when the exact place is missing, it opens the start of the chapter, and when the chapter is missing, the start of the book. It shows no message, and logs a `native-position-fallback` event with the chapter file.

Kobalt recognizes a changed book by the file size and the ZIP directory, which holds the checksum of every file in the book. When the book changes, for example after an update from the store, Kobalt discards its saved position and typography for that book and imports Nickel's position.

The per-book file also records the CREngine DOM version that wrote the position. Kobalt opens the book with that version again, so a saved position stays valid after an update to CREngine. A new book uses the current version.

On firmware 5 and 6, Nickel stores a chapter path, an element ID and a text offset, so a supported position round trip is exact. On firmware 4, Nickel stores only a chapter path and an element ID. Kobalt gives Nickel the element that contains the position and keeps the exact offset locally. If a page has no source element ID, or CREngine normalizes the source text, Kobalt saves the start of the current chapter to Nickel and keeps the exact position locally. This lets Nickel update the current book, sleep cover and percentage without saving an invalid text offset. Ambiguous chapter paths, duplicate IDs and resource read failures still prevent native position writeback.

Kobalt writes Nickel's progress under Nickel's own database lock, through Nickel's own functions, and reads the result back on a separate connection. If the write fails, the local position stays. The write marks the book for normal sync. Kobalt does not claim that the server received it. When a position cannot be mapped to Nickel's format, as in some plain EPUB files, Kobalt records only the time, the reading status and the percentage for a sideloaded plain EPUB. Nickel keeps its own position, and the book is not marked for sync. Other books keep the position locally.

While reading, Kobalt checks Nickel's progress after a sync, an account update, USB and wake, and once a minute otherwise. If a different, newer position arrives, it asks "Keep reading here" or "Go to synced position". It never jumps without asking.

Books downloaded through servers compatible with Kobo's built-in sync mechanism use the server's book ID unchanged. Kobalt accepts safe string IDs in Nickel's download directory, including numeric IDs. It does not require UUID syntax. The EPUB format and protection checks still apply.

At 90% or more on exit, or when you turn past the last page, Kobalt asks whether to mark the book finished. Like Nickel's reader, opening a finished book marks it as reading again.

Kobalt also reports reading sessions and page turns to Nickel, including the estimated words on the page just left. Nickel keeps its reading history and calculates the reading pace. Kobalt refreshes that pace in the background while reading and waits at least a minute after each query completes before requesting another. Page turns use the last valid pace without waiting for Nickel. Kobalt applies that pace to its current chapter word counts and position, and saves the chapter and book time estimates with native reading time. Jumps and layout changes report no words for pace training. On firmware 4, Kobalt accepts either the current reading-session functions or the older pair without a reader-state argument. It requires a complete pair with the same calling convention.

## Reading interface

The reading menu has Chapters, Navigate, Text, Layout, Light and Stats tabs. Search is in the top toolbar. Navigate shows the current page and its neighbors above the book-position bar. Tapping outside the thumbnails keeps them visible. When Default menu style is Default, tapping Navigate again closes the Navigate view and leaves the basic reading menu open. Tapping the middle thumbnail opens that page and closes the controls. Selecting another tab leaves Navigate. Controls > Reading menu > Default menu style chooses Default, Navigate Mode or Stats Mode. Default opens the basic reading menu. Navigate Mode and Stats Mode hide their matching tab and show that view whenever the basic reading menu opens, including after closing Settings. Selecting another tab temporarily replaces the default view. Explicit thumbnail or pinned-Stats choices from older profiles carry over to this setting. Dots mark chapter starts. Minus and plus sit beside the whole-book map and zoom the detailed scrubber out and in around the current or previewed page. Zoom uses 1×, 2×, 4×, 8×, 16×, 24× and 36× steps. A step is available only when its range contains at least 60 pages. Books with fewer than 120 laid-out pages show only the detailed scrubber. At 120 pages, 2× zoom covers 60 pages. Books with more than 1,000 laid-out pages start at the first zoom step that shows at most 1,000 pages, usually between 500 and 1,000. The initial zoom stops at 36× even if that still shows more than 1,000 pages. The range is centered on the reading page and stays within the book. Pagination changes recalculate the initial zoom and whether the map and zoom controls are available. The visible page range and zoom scale appear below the track, with 1× zoom at the full-book range. The whole-book map and its zoom buttons start collapsed. An upward chevron at the right of the page-and-chapter strip expands them above the detailed scrubber. A downward chevron collapses them again. Expanding or collapsing the map keeps the zoom and reading position. The map can stay open at full zoom-out. Its thick, lightly patterned track represents the whole book. Thin brackets mark the visible range. Its track fill uses the paper color while the notches keep their full-book positions. The magnifier has a larger borderless circle of paper color behind it. The brackets keep a minimum grab width at high zoom. A separate tick below the window marks the reading page without crossing the magnifier. The window moves only while zoomed in. The labels have space below them before the detailed scrubber. Both rows have padding above and below their tracks and labels and keep the same height at every zoom level. Drag the window to move the range through the book, or tap elsewhere on the overview to center it there. Moving the range updates the preview without changing the reading position. Manual zoom remains while the reader is open. Pagination or chapter-position changes restore the initial zoom.

Previous and Next sit beside the detailed scrubber, below the map and its zoom controls. Double chevrons preview the previous or next chapter by default. Settings > Controls > Navigate panel > Button action switches between Page jumps and Chapter jumps. Page jumps use single chevrons. Navigate always shows page thumbnails and its navigation controls. Default menu style chooses whether Navigate opens with the reading menu; Default leaves it closed until you select the Navigate tab. These settings are saved for all books.

The page number, total page count and chapter title always appear in a light-gray strip at the top of the navigation panel, in smaller uppercase monospace. The disclosure cell uses the same background. Only the panel’s top edge has a heavy rule; thin rules separate the caption, map, detailed scrubber and tabs. During a preview they describe the selected page. Highlight links and Return to page use buttons centered above that strip. Each button fits its icon and label in a compact row. The Return button adds a plain X with a taller touch target and a hairline separator to discard the return destination. Labels use optical alignment with their icons. Hairlines also separate the map’s zoom buttons from its track. Both buttons have complete borders and a small gap below them, with or without the scrubber. Moving one page in the timeline reuses the overlapping thumbnails and loads only the newly exposed page. The thumbnails update together after that load. The timeline uses an opaque paper background, white in light mode and black in dark mode, so book text does not show behind the cards. Bookmarked pages show the same ribbon shape as the reading page, including in the side thumbnails. The top toolbar never shows a page counter.

Dragging the main scrubber right moves forward through its visible page range. The preview uses up to 90% of the available height and keeps the page proportions. Thumbnails include saved highlights with the same colors and overlap order as the reading page. The preview renders the selected page over an opaque paper background. Smaller preceding and following pages enter from the left and right screen edges, with a gap beside the middle preview. Tap a side thumbnail to bring that page into the middle. Swipe left or right across the previews to preview the next or previous page. A swipe changes only the preview, not the reading position. At the start or end of the book, the missing neighbor stays hidden. Tap the middle preview to go there. Tapping outside the navigation controls keeps Navigate open. Selecting a preview requests a full screen refresh when the destination page is ready to clear the preview frame. Selecting the middle preview closes the reading controls. Reopen the controls to use Return to page and go back to the exact page you left. Scrubbing does not save a new position until you select the preview. Selecting another bottom tab hides the navigation panel and cancels the preview. Sleeping or closing the reader also cancels the preview.

On Kobo, the System tab sits above About. Open books automatically in Kobalt uses the same preference as Kobo's Reading settings. A change in either place appears when the other settings page opens. Turning it off keeps the current book open and uses Kobo's reader for future library openings. A failed save keeps the previous selection.

Text and Layout panels measure their visible controls and messages, including optional font controls. They keep their bottom edge above the navigation bar. When the controls exceed the space below the top toolbar, the controls scroll inside the panel. About measures its content and leaves room for the settings tabs beside it.

Settings > Styling > Book content includes Smart Styling. It is on by default and applies to all books. Kobalt removes margins at forced page breaks and overrides HTML and body margins and padding. Turn it off to keep that publisher spacing. The current book reflows without losing its reading position. Your Text and Layout controls still apply. CSS `@page` rules remain unsupported by the renderer.

A full-size SVG that is the only content in a chapter fills the reading area and follows its SVG aspect-ratio and alignment settings. A full-height table that is the only content in a chapter also uses the reading area, including vertically centred verse. Images and tables alongside other content keep their ordinary layout. Tables at chapter starts retain their chapter break with either spacing preference.

## Custom book styles

`userstyle.css` adds your own CSS to every book. Use it for changes that the Text and Layout panels do not offer, such as paragraph indentation or heading alignment. It changes book content only, not the reader interface.

### Where the file goes

Kobalt does not create the file or ship a default. Create it as a plain text file:

| Platform | Location |
|---|---|
| Kobo | `.adds/kobalt/userstyle.css` on the Kobo drive |
| macOS development app | `~/Library/Application Support/Kobalt/Kobalt/config/userstyle.css`, beside `reader-settings.json` |
| Android | The app-private `config/` directory. There is no in-app file picker or editor. |

Updates keep the file. It is not part of the asset manifest, so editing or deleting it does not affect installation checks.

### When changes apply

Kobalt reads the file each time a book opens. After an edit, close the book and open it again. A changed file also discards cached layouts that were made with other CSS. Appearance previews use the same CSS as the open book. To stop using custom CSS, delete the file or leave it empty.

### How your rules combine with the book's

Your rules go into Kobalt's base stylesheet, after Kobalt's built-in styles and Text settings. CREngine applies them in this order:

1. Ordinary rules in your file rank below the book's own styles. They apply only where the publisher sets nothing.
2. Rules marked `!important` rank above ordinary publisher styles. Use a selector that is at least as specific as the book's.
3. Some Text and Layout settings are already `!important`: line spacing, page margins while Smart Styling is on, alignment when it is not Publisher, hyphenation when it is On or Off, and the font family when a reading font other than Publisher Fonts is chosen. To change those, your rule needs `!important` and enough specificity too. Alignment is set on marked text blocks with an attribute selector, so `p { text-align: left !important; }` is not specific enough; set Alignment to Publisher instead, or use a selector such as `p[data-kobalt-prose]`.

When a reading font is chosen, it replaces every font except code and MathML unless your CSS sets the font itself.

### Examples

```css
/* Remove paragraph indentation. */
p { text-indent: 0 !important; }

/* Add space between paragraphs. */
p { margin-top: 0.5em !important; margin-bottom: 0.5em !important; }

/* Centre chapter headings. */
h1, h2 { text-align: center !important; }
```

### Limits

The file must be at most 256 KiB and must not contain NUL bytes. Kobalt ignores a missing, unreadable or oversized file, and the book still opens. Rules use the CSS that CREngine supports. CREngine handles CSS syntax errors itself; they never cause an installation error. Font fallbacks stay built into the app and cannot be changed here.

Ordinary turns on i.MX and unknown backends use one whole-screen update with their existing mode and waveform. On MediaTek, a page turn that needs image cleanup uses one whole-screen quality refresh. Kobo selects GC16 for greyscale cleanup, GCK16 for dark greyscale cleanup and GCC16 for colour cleanup. Entering dark mode requests one whole-screen cleanup. In light mode, opening the plain reading bars over a text-only page uses one screen-spanning partial text update without cleanup, so the top and bottom appear together. Bottom panels keep localized updates. Opening the menu in dark mode requests one whole-screen cleanup. Closing the menu with a tap on the page or the title requests one full cleanup to clear ghosting. In dark mode, returning from the menu also requests cleanup when it closes another way. In light mode, closing a panel another way, or jumping from Chapters or Search, does not flash. Refresh the screen, on the Display tab, decides which page turns also flash. Smart, the default, flashes on a forward turn onto the first page of a chapter, but only after at least 10 turns since the last flash, so a run of short chapters does not flash on every turn. Every page flashes on each completed forward or backward page turn. Rejected page-turn gestures, including turns past the book edges, do not add a flash. Every chapter flashes at every chapter start. Every 6, 10 or 20 pages flashes on that many turns since the last flash, in either direction. Manually flashes only when the menu closes. Any flash restarts the count. Each flash logs a `full-flash` event with its reason, and replaces that turn's page animation.

An already visible layout progress bar repaints only the strip where its fill changes, in either direction. Its border and unchanged fill stay untouched. Values received in the same event-loop pass paint together, and values that leave the fill on the same pixel do not repaint. On MediaTek, percentage-only updates inside an already visible layout progress bar use partial mode in light mode over a text-only page. Showing or hiding the modal, changing its message or layout, dark mode and image cleanup keep their existing refresh policy. Stats keeps unchanged graph data and progress without repainting. Text, Layout and Stats use their final position before they become visible. Opening Text or Layout keeps the current book frame until an appearance setting or viewport size changes. Appearance panels keep their position when an unchanged reading state is reported. Chapters and the font picker keep their stacking order. Replaying those states does not repaint the panels. Adjacent or split widget rectangles with the same supported refresh policy merge into one submission after Qt finishes painting them. Damage with different update modes or waveforms keeps each rectangle's policy. Header and footer changes keep separate damage regions when no page turn is in progress. Showing or hiding link highlights repaints the whole page in one refresh, because MediaTek refreshes each page rectangle separately. A change between two sets of highlights updates only their old and new outlines. Annotation changes repaint one compact rectangle that covers the old and new marks. Unchanged annotation state does not repaint. Closing highlight mode without an unfinished selection leaves the reading page unchanged. Discarding an edit restores the original saved highlight. A destination page arrives with its visible saved highlights and draft selection. They paint together in the first reading frame, including page animations. Opening a book with saved highlights prepares that markup before replacing the opening view. Pages without visible markup keep the ordinary page path. Paging Stats, Chapters, Bookmarks or licenses leaves unchanged headings and figures alone. Opening progress batches values within the current event-loop pass, without a timer. Opening a bottom panel or returning from the font picker keeps the toolbar rules in place. Compatible key damage within the visible search keyboard uses one rectangle instead of one refresh per key. Showing an already visible keyboard keeps its stacking order. Unchanged keyboard-only paints skip submission when their pixels already received the same refresh policy. Changed keys and cleanup still refresh. Brightness and warmth notices skip unchanged rounded levels.

Page animations work on the Clara Colour, Libra Colour and Clara BW, which use MediaTek's `hwtcon` display driver, and follow NickelDissolve's sweep. Animations work in light and dark mode. Text and small greyscale images can use the sweep. A turn onto or away from an image covering at least 10% of the reading image replaces the animation with one whole-screen image-quality refresh. On colour devices, colour regions, including coloured text and backgrounds, also replace the animation with that refresh. Colour alone does not trigger this policy on monochrome devices. Both the outgoing and incoming pages are checked. Kobalt keeps the final page pixels throughout the turn and does not flash image regions separately after a sweep. These are Kobalt's conservative thresholds, not a claim about Nickel's internal thresholds. A failed band or wait requests whole-page cleanup instead of leaving stale bands. Each animated turn logs a `page-animation` event. Animations are off by default. On other devices, including the Elipsa 2E and Tolino models, the option is greyed out. `--no-page-animations` removes them from a build.

Kobalt installs its animation hook when its reader first opens, after startup mods have loaded. It preserves the existing display hook so older NickelDissolve installations keep controlling the built-in reader's animations. The two animation settings are independent. An `animation-hook` event records whether installation succeeded; if it fails, Kobalt leaves its animation setting unavailable. This supports mods loaded at startup. Mods that replace the same hook later without preserving it can still conflict.

Ordinary page turns reuse chapter pages and the available font list in memory. Chapter pages update when the pagination or the chapter list changes. A turn with unchanged appearance and viewport skips appearance validation; rotation can change the viewport without opening Settings. Adjacent page images are prepared after the current page is painted. One retired page buffer can be reused when no session or interface holds its pixels. Resize, appearance changes and image-resource changes discard it. Images discovered on adjacent pages load before those pages are requested.

## Sleep, USB and power

Before sleep, Kobalt saves its position and pauses its work. The page stays on screen until Nickel's sleep screen is ready. Kobalt then shows the sleep screen with one full refresh, which also clears the page, so the screen flashes once, as in Nickel's own reader. After wake, Kobalt waits for Nickel's sleep or PIN view to close and for USB storage to finish remounting. It then checks authorization and restores page-turn input before it shows the book again. The frontlight can finish fading in while the page is already visible. If wake or USB cancellation arrives while the previous operation is still releasing resources, Kobalt completes that release before checking authorization again.

On Kobo, Settings > System has a Sleep screen row. It opens a choice of Kobo's built-in sleep screen, Kobalt with book cover or Kobalt with reading page. Kobo's built-in screen is the default. The cover option first tries Kobo's full-screen cached cover, then the cover embedded in the book. It fits the image without cropping or dimming it. Empty space around the cover is always black in both light and dark mode. If neither cover is usable, it falls back to the reading page. The sleep-screen choice is hidden on hosts without Kobo sleep-screen support. The reading-page option shows the current page slightly darkened. Both Kobalt options show a card on the left with the percentage read. Its heading says Sleeping, Charging or Charged, using Nickel's charge state. A battery icon and percentage sit in the top-right corner of the card only while charging or charged. The icon shows the battery level and adds a bolt while charging. While asleep, the card updates when Nickel reports a battery level or charging change. Unplugging hides the battery and restores Sleeping. These updates do not poll the battery or decode the cover again. The heading uses Kobalt's serif interface font. Reading progress and time use sans-serif text. The battery percentage uses smaller monospaced text, with space before the icon. Clock slots show a lock icon in the reading-page sleep image. The reading page keeps its clock. The card also shows the estimated time left when Nickel has a reading pace. Estimates up to 120 minutes use minutes; longer estimates use hours and minutes. Menus and dialogs are omitted. An unavailable or changing reading page uses the stock sleep screen. Kobo still controls sleep, wake and PIN entry. Closing a book saves the selected Kobalt backdrop before returning to Kobo. USB handoff also saves it before storage is exported, when the final save completes within its deadline. The same backdrop is used when locking or turning off from Home or the library while that book remains the last book opened. Turning off with a Kobalt book open uses its current backdrop. The card says Powered off during shutdown. Its background is black and its text is white in both light and dark mode. Restarting keeps Kobo's normal restart screen. Opening any book again invalidates the saved image, including opening the same book in Kobo's reader. A missing, damaged or outdated image uses Kobo's built-in screen. The saved image survives a Nickel restart if Kobo's last-read record still matches. The charging card uses the current battery state and continues to update while asleep. The setting does not change Kobo's sleep-screen configuration. Profiles that had Kobalt's sleep screen enabled start with the cover option.

Below it, Sleep screen style chooses how the Kobalt options show their status: Card, Footer band or Bookmark. Card is the default and is the card described above. Footer band is a strip across the bottom edge. Its top line is thicker for the part of the book already read. The status uses the serif interface font on the left. Progress and time left use small monospaced capitals on the right. Bookmark is a ribbon that hangs from the top edge near the right side, with a notch cut into its end. It is black in light mode and dark gray in dark mode, with a white outline. It shows the status as a small caption, the percentage read in large serif figures and the time left below. In both styles, the battery shows only while charging or charged. In the band, it stands upright after the status, as tall as its letters, with its percentage on the right. The space before it equals the space between the screen edge and the status. In the ribbon, it sits at the end. Each style keeps one fixed area, so a battery update repaints and refreshes only that area. Powered off makes the band black with white text and keeps the black ribbon. Sleep and power-off from Home use the style selected when the device sleeps. Images saved by earlier versions have no percentage; the band then shows no progress line and the ribbon shows the progress text instead. The style has no effect with Kobo's built-in sleep screen. Like the Sleep screen row, it is unavailable on hosts without Kobo sleep-screen support.

Nickel's USB confirmation appears above the open Kobalt page. Cancel keeps the book open.

A confirmed USB connection saves the local position and attempts to save native progress before Nickel starts its USB workflow. The native save keeps newer Nickel progress, allows two seconds for position conversion and does not wait for another database writer. A failed or timed-out save does not cancel USB. Kobalt then closes the book and releases every file on user storage before Nickel exports the storage. If access to the book is revoked during the save, Kobalt still completes this cleanup and USB handoff. Reopen the book from the library afterwards.

Power-off and reboot wait for Kobalt to save reading time and progress before Nickel closes its database. When the application exits, Kobalt stops its engine worker before releasing any remaining cached book models.

## Limits

Kobalt tolerates repeated manifest items when every attribute matches. Conflicting declarations with the same ID remain unsupported.

- ZIP64 archives are not supported. Resource encryption is unsupported except for IDPF and Adobe font obfuscation.
- SVG input elements can nest up to 64 levels. Rendering skips references that would extend an active SVG reference chain beyond 16 levels.
- Resources are limited to 32 MiB each, and the source cache to 32 MiB in total. Images above the limits show a placeholder. An optional image that cannot load shows a warning and does not stop later images from loading. Renewing the source allows another attempt. Cancellation, revoked access and changed resource bytes still stop the session. Interlaced PNG images whose decoded storage exceeds 64 MiB are not rendered, including images embedded inside other resources. The parsed document, fonts and page images are outside the source-cache budget.
- Typography changes lay out the whole book again. There is no partial reflow.
- Hyphenation dictionaries cover only the languages listed above.
- Notes and custom tap zones are not available.
- Android and desktop reading-time estimates approximate words per page from each chapter's word count and layout. Illustrations and uneven text density can affect accuracy. Kobo uses Nickel's pace and Kobalt's source word counts.

## Hardware validation

Device testing includes installation and reading on Clara Colour, Clara BW with firmware 4.45 and Libra 2 with firmware 4.38. Manual rotation and touch targets were confirmed on Clara BW with firmware 4.45. Page animations with NickelDissolve installed were confirmed on Clara BW with firmware 4.45. Dark-mode refresh quality, sleep with a PIN, rotation on other models and firmware versions, page buttons on Libra Colour, the Home button on Touch models and server sync still need hardware validation.

## Android standalone reader

Reading time pauses when Android puts the app to sleep or it becomes inactive. It resumes when the app is active and the reading page is visible. A book that finishes opening in the background does not start counting time until the app becomes active.

Debug builds appear as Kobalt on the home screen. They use a separate app ID from releases and add `-debug` to the displayed version. Both apps can be installed together. Each keeps its own books, settings and reading progress.

Android uses the shared reader UI and unprotected EPUB pipeline without Nickel. The app starts in the [library](#library). On first use, Open a single book opens the document picker; Choose folder opens the system folder picker and scans for books. Books opened individually or through another app's Open with menu join the library and open immediately. Imports are copied into app-private storage, with a 128 MiB limit. Reading position, bookmarks and settings stay on the device. While opening, Kobalt shows the same loading layout, logo, progress bar and delayed hint as Kobo. System Back cancels opening or returns from the reader to the library. At the root library, system Back leaves the app. Volume Down and Page Down advance on the initial key press; Volume Up and Page Up go back. These keys follow the reading order in both left-to-right and right-to-left books; touch swipes follow the page direction. Holding or releasing a key does not request another turn. Device button remapping can affect when Android delivers these events. Protected or invalid EPUBs show an error over the library; Android has no built-in Kobo reader to hand them to. See [Android limitations and setup](building.md#android).

The Android launcher icon is an outlined open book with Kobalt's serif K and a bookmark. The artwork fills more of the icon while leaving space for the launcher’s adaptive mask.

Android follows the device’s rotation setting on the start screen, in the library and on the reading page. Its Layout menu omits Kobo’s manual rotation controls. Android shows system bars on the start screen and in the library, and hides them while reading. The book-opening screen stays visible until the system bars finish hiding and the first page is ready at the final reading size, with its discovered images loaded. On Android, the reader uses the canvas inside the system safe area. Camera cutouts and visible system bars reserve space around the reader. The top status row and bottom navigation stay within that area when the phone rotates or the insets change.

### Downloaded dictionaries

Dictionary downloads are disabled on Kobo, and its settings omit the Dictionaries tab. Kobo lookup uses Nickel's installed dictionaries, including dictionaries in `.kobo/custom-dict`. Standard and custom dictionaries remain separate choices when they share a language suffix. Custom choices keep Nickel's custom label and are saved by file path, so installing or removing the standard dictionary does not change the selected custom dictionary. Lookup uses the installed entry shown in the selector even when Nickel lists an uninstalled standard dictionary with the same language suffix. The Kobo reader does not start the download manager or use dictionaries previously downloaded through Kobalt.

On desktop and Android, open the Dictionaries tab below Styling in settings to install and remove downloaded dictionaries from one paged list. Dictionaries for the book's language appear first, followed by other languages. Monolingual dictionaries come before translations. Get starts a download immediately. A circle in the Stop button shows download progress without changing the row height. Section headers have a gray background, and a divider separates the storage footer. Remove asks for confirmation before deleting an installed dictionary. The footer shows space used and available. The catalogue contains the dictionaries from DanielGregorini's [koreader-dicts](https://github.com/DanielGregorini/koreader-dicts) release v1.2.0. Downloading requires an internet connection.

Downloads run in the background and can be cancelled. Kobalt checks the release's SHA-256 digest before installing. Failed or cancelled installs do not become available for lookup. Licenses and attribution stay with the downloaded files on user storage.

The lookup selector uses the same dictionary names and order. Its list overlays the definition without changing the definition layout or page count. The definition pager is hidden while the list is open, so only the selector pager is visible. Kobo entries with multiple parts of speech retain separate headings and definition lists. Lookup first uses an installed dictionary for the book's language, with monolingual dictionaries first, then platform dictionaries, then installed dictionaries for other languages. Choosing another dictionary applies to that book. The choice is saved with the book and restored on reopening. If the dictionary is unavailable, lookup uses automatic selection. Removing the chosen dictionary restores automatic selection. The StarDict reader uses the supplied inflection index and reads compressed definitions as needed. It prefers exact spelling before a case-insensitive match, so an uppercase acronym does not replace a matching lowercase word. Kobo's built-in dictionaries are kept.

Reader confirmations use shared notice and choice modals with a required title, an optional description and an optional image. Dictionary removal and restoring appearance defaults open over the settings sheet. A notice has one action. A choice has two actions. The primary action is filled and the secondary action is outlined. Actions share padding and stack vertically with the primary first when their labels do not fit in one row. Long labels wrap inside the buttons. The font selector points up toward its picker panel.

Chapters, bookmarks, dictionary choices, reading header and footer size choices, and acknowledgments share list rows and caption strips. One, two and three text lines use shared row heights. Bookmark and annotation rows use the selected reading font for excerpts. The annotation list reserves two excerpt lines per row so it can paginate before requesting text. It fetches only the current page of excerpts and releases those details when the list closes. Bookmarks retain their content-dependent row height. Current rows are inverted, pressed rows use the existing gray highlight, and long titles end with an ellipsis. Moving a pointer over reader controls does not highlight or repaint them. Row press feedback ends on release, including when a list reopens with keyboard focus on that row. Search results also use book-font excerpts and the shared list spacing and dividers.

Long lists wrap when paged. Next on the last page returns to the first page, and Previous on the first page opens the last page. This applies to Chapters, Bookmarks, Search results, font choices, dictionary choices, downloaded dictionaries and the acknowledgments list. Empty and single-page lists disable both page actions. Dictionary definitions, footnotes, license text and the chapter graph keep their page boundaries. Paging a list does not change its selected item.

### Finding links

Controls settings includes Tappable links with three choices: Off, Footnotes only, and Footnotes and links. Off is the default and keeps the existing tap behavior. Footnotes only uses the same note detection as Follow link. Footnotes and links also includes passage, website and unavailable links. The choice applies to all books and survives a restart. Links keep their existing styling in both themes. Kobalt's default link style is underlined; a publisher can override it. Enabling direct taps does not change pagination.

Tap inside the link text to follow it through the existing note popup, passage navigation or website confirmation. Direct taps take priority over page tap zones and the bookmark corner, including when page-turn taps are disabled. Taps outside the link text keep the configured page, menu and bookmark actions. Direct taps are inactive while reading controls are open or annotation mode is enabled. Long presses keep word selection, dictionary lookup and Follow link. Highlight links remains available in all three modes.

Kobalt keeps the book’s link styling. When reading controls are open, pages containing links show a compact Highlight links button with the link count above the scrubber or bottom tabs. Tap the button to reveal the links: each link gets a gray background and an outline. Tap a link to follow it; the reading controls stay closed. Reveal mode hides the normal toolbars so they cannot cover links. A label replaces the header strip, or the footer strip when the header is too small, in that strip’s face and size: “Tap a highlighted link to follow it” on the left and “Tap elsewhere to exit” on the right. Tap anywhere except a link, the label included, to leave reveal mode. You return to the reading page with the toolbars closed, whether you opened highlight mode from the controls or the link indicator. The dismissal tap does not also open the controls or turn a page. In ordinary reading, a long press on link text selects only the word under your finger and opens its selection popover. Dictionary, Follow link and Clear selection share one connected row. Dictionary opens only when chosen. The menu has no annotation actions. Enable highlight mode in the reading menu before selecting text to annotate. Follow link is available in the regular selection popover and is omitted from the marking popover.

Controls settings includes “Show link indicator while reading”. It is off by default. When enabled, pages containing links show a small button with a link icon and the link count at the right of the footer, level with the page number. Without a footer it sits just above the bottom edge. The button opens the same reveal mode. The indicator covers all links, regardless of publisher styling. Revealing links does not change pagination.

Fonts with an optical-size axis show an Optical size slider below Text size. The slider uses whole-point steps and does not change the text size. Fonts use their declared optical-size default, rounded to a whole point. The manual value is saved with the book and restored after reopening. Fonts without this axis hide the row.

## Library

The library is the starting screen on Android and in the desktop app. It shows books in the folders the user adds and books opened individually, including external Open With requests. Closing a book returns to the library. There is no separate intro screen. Kobo has no library; Nickel shows the books there.

On first use, the library header stays visible above a compact empty state with Open a single book and Choose folder. Sorting, view choices and paging stay hidden until books or a folder are added. On Android, Choose folder opens the system folder picker. Kobalt keeps read access to the folder after restarts and reads its books in place, including subfolders. Hidden folders and files are skipped. Opening a library book copies only that book into a cache in app-private storage; the copy of the previous book is deleted. On the Mac, File → Add Library Folder also adds a folder.

The header shows Library and the number of books, with Search and More cells. The Library is the root screen and has no Back cell. Below it, the sort caption opens the sort and filter choices, and three cells switch between the views: Home, List and Cover grid. The view is one setting for the whole library, and Cover grid is the default. The sort applies to List and Cover grid; on Home the caption reads Now reading and opens nothing. Views show pages, not a scrolling list. The pager turns them, and a horizontal swipe does the same.

- Home shows only the books in progress, as large covers from the top of the page, the most recently opened first. Under each cover, the bar and the percentage show how far it is read. With none in progress, it says that books you are reading appear there.
- List shows one row per book with a large cover, the title, the author and the series. The right column shows the percentage read with a bar, New or Done.
- Cover grid shows only covers, in 2:3 cells. A book in progress has a thin outlined bar under its cover that shows how far it is read. Cover size, in the sort and filter choices, sets a target width: Small, Medium (the default) or Large. The grid uses the nearest whole number of columns and rows for that width, and covers shrink a little to fill the page both ways. Medium shows 4 by 3 covers on the 6- and 7-inch previews. Long-press a cover to see its title and author.

Sort by Recently opened, Recently added, Title, Author or Series. The series comes from the book's EPUB 3 collection metadata or Calibre's series tags. Show All books or Hide finished. Titles and authors sort without case or accents, and numbers in titles sort by value. Search filters the current view by title, author and series, without case or accents. Each view shares the space a page cannot use equally above, between and below its rows, so pages look the same on every screen size.

Tap a book to open it; a pressed cover gets a heavy frame and a pressed row turns gray. Long-press a book for Continue reading or Start reading, Mark as finished, Mark as unread and Remove from library; a patterned backdrop covers the library behind this menu. Mark as unread returns a book to Not started, clears its book-specific settings and restarts it at the beginning. Bookmarks and annotations stay saved. On its next opening, the book uses the current text defaults, including inherited settings when enabled. On Kobo, marking a book unread in Nickel also clears Kobalt’s saved settings and position when it is next opened. Removal asks first. It does not delete a book file in a folder, and the book comes back when the folder is scanned again. On Android, removing a book opened on its own deletes Kobalt's copy of it. Reading progress stays on the device.

A book is Reading after it was opened, and Finished when the reader saved it as finished or it was marked as finished. Progress comes from the reader's saved page when the book closes.

More opens Add folder, Open a single book and Library folders, with folder-plus, open-book and folders icons. These actions share a framed card with the book menus and a patterned backdrop over the library. Tapping outside closes the menu without opening a book. Library folders lists each folder with its number of books. Remove a folder to take its books out of the library; the files and reading progress stay on the device. Check for new books at start is on by default. Rescan all folders checks every folder now.

The first scan of a folder reads the title, author, series and cover of every EPUB in it. Later scans compare file names, sizes and dates, and read only new or changed books. A Kobalt update that reads more metadata reads every book once again. Books whose files are gone leave the library. Protected and unreadable files are not shown. While a scan runs, the sort caption shows the number of books found, with the six-square loading indicator, and the library redraws at most once a second. The library catalogue is saved in `kobalt.sqlite`, with cover thumbnails in `library-covers/`. Library preferences stay in `reader-settings.json`. Existing `library.json` catalogues are imported and retained under `migration-backup/`. Damaged or unsupported catalogues are preserved and block saves until the problem is resolved.

List rows share all the space between the view toolbar and the pager, without the cover grid's top gap. Rounding is distributed across row boundaries, so no strip is left below the last full row.

The library follows the reader's dark mode setting.

On Android, the Qt window and activity both use edge-to-edge layout. The activity reports its surface bounds and visible system-bar and cutout insets together. The Library reserves this space on cold launch as well as after closing a book. Showing or hiding the bars updates the content area even when the screen dimensions stay the same.
